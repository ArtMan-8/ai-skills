# English basic pack

Базовый пакет для англоязычного технического текста: рабочая систематизация ключевых норм контролируемого английского. Это не полный внешний стандарт, не официальный словарь и не гарантия соответствия. Пакет применяется вместе с языково-нейтральным ядром из `SKILL.md`.

Не применяй пакет к русскому тексту (для него есть `references/rules.md`), к маркетингу, юридическим и художественным текстам. Стилевую правку таких текстов выполняй только по прямой просьбе и не выдавай её за техническую редактуру. Не переводи текст на английский и с английского без отдельного запроса.

## 1. Определи тип текста

|               | Процедура (инструкция)                           | Описание (объяснение)                                               |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| Цель          | Сказать читателю, что сделать                    | Объяснить, что это и как работает                                   |
| Форма глагола | Повелительное наклонение: `Install the package.` | Простое настоящее/прошедшее/будущее: `The service reads the queue.` |
| Предел        | **20 слов** в предложении                        | **25 слов** в предложении                                           |
| Единица       | Одна инструкция в предложении                    | Одна тема в абзаце, не больше шести предложений                     |

Не смешивай типы в одном фрагменте. «Getting started» — процедура. «Architecture» — описание. Примечание внутри процедуры — описание.

## 2. Ключевые правила

### Слова

- Один термин — одно понятие, одна часть речи. Не чередуй `check / verify / confirm / validate`; выбери одно.
- Унификация термина не меняет условия, порядок и область действия утверждений.
- Технические существительные и глаголы предметной области разрешены: `webhook`, `commit`, `deploy`.
- Не используй сленг, жаргон и метафоры. Не превращай техническое существительное в глагол и наоборот.
- Базовые модальные глаголы: **can, will, must**. Избегай `should`, `would`, `might`, `could`.
  - требование → `must`;
  - возможность или разрешение → `can`;
  - совет → изложи фактом или удали;
  - `may`, выражающий возможность или вероятность, сохраняй: замена на `can` или `must` меняет смысл (возможность → способность или обязанность). Точность смысла важнее словаря; отступление отметь.
- Не строй фразовые глаголы, если есть один глагол: `set up` → `configure`, `go down` → `decrease`. Не оставляй фразовый глагол и его замену одновременно: одно действие — один глагол.
- Американская орфография по умолчанию: `color`, `behavior`, `license` (существительное). Если проект явно принял британскую орфографию, следуй проекту и не смешивай варианты.

### Существительные

- Не больше трёх слов в составном термине. Длинную цепочку разрывай предлогами: `the connection pool timeout configuration value` → `the timeout value for the connection pool`.
- Сокращение или короткую форму вводи после полного названия, если она нужна.

### Глаголы

- Только простые формы: инфинитив, повелительное наклонение, простое настоящее, прошедшее, будущее, причастие прошедшего времени как прилагательное.
- Не используй present perfect и сложные вспомогательные конструкции: `has completed`, `is being rebuilt`, `is to be installed`.
- `-ing` — только существительное или часть термина (`logging`, `mounting bracket`), не глагол.
- Действительный залог. В описании пассив допустим, только если исполнитель неизвестен или несуществен.
- Действие — глаголом, не номинализацией: `perform compression of the file` → `compress the file`.

### Предложения

- Короткие и полные: не выбрасывай артикли, `that` и другие служебные слова ради краткости.
- Без сокращений: `you'll` → `you will`, `it's` → `it is`.
- Условие — перед командой: `If the build fails, read the log.`
- Не вводи обязательные союзы или конструкции сверх правил пакета. Если условие уже выражено однозначно, не переписывай его ради формы.
- Одна инструкция в предложении. Две допустимы, только если действия выполняются одновременно.
- Сложное перечисление — вертикальным списком.
- Связки между предложениями используй по делу: `Then`, `As a result`.

### Процедура

- Повелительное наклонение: `Run the migration.`
- Не больше 20 слов.
- Одна команда в предложении.
- Условие и предупреждение — до команды.
- Примечание даёт информацию, а не команду; к нему применяется предел 25 слов.

### Описание

- Простое настоящее/прошедшее/будущее время; без повелительного наклонения.
- Не больше 25 слов в предложении.
- Одна тема в абзаце, не больше шести предложений.
- Новый факт — постепенно, по одному на предложение.

### Предупреждения

- `WARNING` — риск для людей, `CAUTION` — риск для оборудования или данных.
- Сначала команда или условие, затем риск: `CAUTION: Do not use the --force flag on production. The flag deletes rows that do not match the source.`
- Не прячь команду после объяснения.

### Пунктуация и подсчёт слов

- Точка с запятой не используется: раздели на два предложения.
- Скобки допустимы для ссылок, обозначений, расшифровок и пояснений.
- Одно слово считаются: число, число с единицей, аббревиатура, буквенно-цифровой идентификатор, цитируемый текст, заголовок, метка, имя собственное, слово через дефис.
- Код в обратных кавычках считается одним словом.

### Неприкосновенное

Не меняй: блоки кода, код в строке, идентификаторы, команды, флаги, пути, цитируемые сообщения об ошибках и строки журнала, названия продуктов, эндпоинтов и ключей конфигурации, числа с единицами.

### Термины и перевод

- Термин без утверждённого перевода оставляй в оригинале: `idempotency`, `payload`, `sidecar`, `webhook`.
- Не подбирай «похожий» перевод и не заменяй точный термин общим (`payload` → `message`, `idempotency` → `reliability`).
- Пояснение при первом употреблении допустимо, но не выдавай его за определение.
- В глоссарии проекта фиксируй статус: `original`, `approved translation`, `not approved`, `do not translate`.

## 3. Базовые замены: вода → факт

| Было                             | Стало                                              |
| -------------------------------- | -------------------------------------------------- |
| leverage, utilize                | use                                                |
| in order to                      | to                                                 |
| prior to                         | before                                             |
| ensure                           | make sure that                                     |
| it is worth noting that          | (удалить)                                          |
| it's important to, crucially     | (удалить, сказать факт)                            |
| simply, just, easily, seamlessly | (удалить)                                          |
| robust, powerful, comprehensive  | (удалить или назвать измеримое свойство)           |
| functionality                    | function, feature                                  |
| enables you to, allows you to    | you can                                            |
| is designed to, aims to          | (удалить, сказать, что делает)                     |
| facilitate                       | help, make possible                                |
| when it comes to                 | for                                                |
| in the event that                | if                                                 |
| due to the fact that             | because                                            |
| and/or                           | выбери одно или напиши `X, or Y, or both`          |
| e.g. / i.e. / etc.               | for example / that is / назови элементы            |
| gracefully handles               | назови действие: `retries three times, then stops` |
| out of the box                   | by default                                         |
| under the hood                   | internally                                         |

## 4. Самопроверка

1. Посчитай слова в трёх самых длинных предложениях. Больше 20 в процедуре или 25 в описании — раздели.
2. Найди сокращения, `has been`, `have been`, `should`, `-ing` после запятой, точку с запятой.
3. Найди каждое `if` и `when`. Условие должно стоять в начале своего предложения, перед командой.
4. Проверь, что для понятий «проверить», «настроить», «запустить» выбран один термин и он не чередуется.
5. Проверь, что код, идентификаторы, пути и строки ошибок не изменены.

## 5. Примеры

### Процедура

**Было:** `You'll want to grab the API key from the dashboard before configuring the client, which you can do under Settings.`

**Стало:** `Get the API key from the dashboard, under Settings. Then configure the client with this key.`

### Описание

**Было:** `The implementation of the validation of the configuration is performed prior to the execution of the service.`

**Стало:** `The configuration is validated before the service is executed.`

Если `validation` — отдельный этап, а не действие: `Configuration validation is performed before the service is executed.`

### Предупреждение

**Было:** `Note that data loss may occur in some circumstances if the destructive flag happens to be enabled when running against production.`

**Стало:** `CAUTION: Do not use the --force flag on production. The flag deletes rows that do not match the source.`

## 6. Границы

- Это базовый пакет, а не полный внешний стандарт. Не заявляй соответствие и не ссылайся на пункты, которых нет в этом файле.
- Официальный словарь не воспроизводится. Для строгого режима нужен словарь проекта.
- Не применяй пакет к маркетингу, юридическим и художественным текстам; стилевую правку выполняй только по прямой просьбе.
- Не переводи на английский и с английского без отдельного запроса.
- Если язык текста не английский и не русский, применяй только языково-нейтральное ядро и скажи об этом.

# Каталог языковых правил

**Сила:** `mandatory` — обязательное поведение при наличии предпосылок; `preferred` — предпочтение с контекстными исключениями; `heuristic` — диагностический ориентир, не автоматический запрет. Правила описывают поведение редактора, а не универсальные требования ко всем документам.

## SEM — точность смысла

| ID      | Сила      | Правило                                                                                                                                                    |
| ------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEM-001 | mandatory | Сохраняй возможность, обязанность, разрешение, рекомендацию и степень уверенности. Меняй грамматическую форму, только если смысловой тип остаётся прежним. |
| SEM-002 | mandatory | Сохраняй область действия отрицания.                                                                                                                       |
| SEM-003 | mandatory | Не опускай существенные условия и исключения; сохраняй их привязку к тому же действию и результату.                                                        |
| SEM-004 | mandatory | Не подменяй временную последовательность причинностью.                                                                                                     |
| SEM-005 | mandatory | Сохраняй значения, единицы, границы и количественные ограничения.                                                                                          |
| SEM-006 | mandatory | Различай факт, предположение, гипотезу, рекомендацию и требование.                                                                                         |
| SEM-007 | mandatory | Не разрешай содержательную неоднозначность вымыслом; не добавляй отсутствующие сущности, числа и поведение.                                                |

## TERM — терминология

| ID       | Сила      | Правило                                                                                                                                                                           |
| -------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TERM-001 | preferred | Поддерживай устойчивое обозначение понятия; не чередуй названия одного понятия без основания.                                                                                     |
| TERM-003 | mandatory | Не упрощай технический термин ценой изменения смысла.                                                                                                                             |
| TERM-004 | mandatory | Сохраняй идентификаторы, API, команды, пути, ключи, литералы и составные технические обозначения дословно: не переводи, не переименовывай, не разбивай на части и не переставляй. |
| TERM-006 | mandatory | Учитывай доступный проектный справочник терминов, проверяя его применимость.                                                                                                      |
| TERM-008 | mandatory | Не объявляй разные обозначения эквивалентными без оснований.                                                                                                                      |
| TERM-009 | mandatory | Выявляй конфликты вместо автоматического разрешения; сообщай о конфликте справочника с другими материалами.                                                                       |
| TERM-010 | mandatory | Не утверждай доменные определения без оснований или подтверждения.                                                                                                                |
| TERM-011 | preferred | Предлагай один общий справочник только при существенной потребности, не для каждого документа.                                                                                    |

## SYN — синтаксис

| ID      | Сила      | Правило                                                                      |
| ------- | --------- | ---------------------------------------------------------------------------- |
| SYN-001 | preferred | Предпочитай структуру с ясными логическими связями.                          |
| SYN-002 | preferred | Указывай субъект действия, если он известен и существенен; не выдумывай его. |
| SYN-003 | preferred | Сокращай избыточную вложенность.                                             |
| SYN-004 | mandatory | Устраняй неоднозначность референтов, определений и условий.                  |
| SYN-005 | heuristic | Оценивай длину по сложности, не по жёсткому лимиту слов.                     |
| SYN-006 | preferred | Не объединяй независимые утверждения ради плавности.                         |

## LEX — лексика

| ID      | Сила      | Правило                                                                         |
| ------- | --------- | ------------------------------------------------------------------------------- |
| LEX-001 | preferred | Предпочитай конкретный глагол громоздкой номинализации, если смысл сохраняется. |
| LEX-002 | preferred | Удаляй слова без смысловой или коммуникативной функции.                         |
| LEX-003 | mandatory | Не заменяй точное обозначение более общим с потерей различия.                   |
| LEX-005 | preferred | Избегай разговорной образности, если она создаёт неоднозначность.               |
| LEX-006 | preferred | Избегай неоправданно канцелярских конструкций.                                  |
| LEX-007 | heuristic | Выбирай между заимствованным и русским термином по контексту и соглашениям.     |

## COH — связность

| ID      | Сила      | Правило                                                                      |
| ------- | --------- | ---------------------------------------------------------------------------- |
| COH-001 | preferred | Поддерживай понятную последовательность мыслей.                              |
| COH-002 | mandatory | Делай существенные логические связи явными, если иначе возможно разночтение. |
| COH-003 | mandatory | Не добавляй «поэтому» и другие причинные связки без оснований.               |
| COH-005 | preferred | Не добавляй вводные слова только ради видимости связности.                   |

## CON — краткость

| ID      | Сила      | Правило                                                                                                  |
| ------- | --------- | -------------------------------------------------------------------------------------------------------- |
| CON-001 | preferred | Устраняй смысловую избыточность.                                                                         |
| CON-002 | mandatory | Не сокращай за счёт условий, ограничений и логических отношений; не сливай разные случаи в одно условие. |
| CON-003 | preferred | Избегай телеграфного стиля, затрудняющего понимание.                                                     |
| CON-005 | heuristic | Не вводи количественный лимит длины без запроса.                                                         |

## NOR — нормы языка

| ID      | Сила      | Правило                                                                   |
| ------- | --------- | ------------------------------------------------------------------------- |
| NOR-001 | mandatory | Соблюдай орфографию, грамматику и пунктуацию современного русского языка. |
| NOR-002 | mandatory | Соблюдай нормативное управление и сочетаемость, учитывая контекст.        |
| NOR-003 | mandatory | Не объявляй допустимую конструкцию ошибкой лишь из-за необычности.        |
| NOR-006 | preferred | Среди допустимых вариантов предпочитай наиболее ясный.                    |

## GEN — процесс написания

| ID      | Сила      | Правило                                                                                                                                                                                                 |
| ------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GEN-001 | mandatory | Не добавляй неподтверждённые технические сведения ради полноты или убедительности: место настройки, причину, назначение поля или флага, состав продуктов, числовые примеры, в том числе иллюстративные. |

## Разрешение конфликтов

Семантическая точность важнее краткости и гладкости. Техническая неоднозначность требует уточнения, а не домысла. Терминологическое единообразие не отменяет различий между понятиями. Пассивный залог, длинное предложение, повтор и непрямой порядок слов могут быть корректными. Минимизируй необоснованные правки.

Явное указание пользователя на форму, лимит или замену имеет приоритет над предпочтениями каталога, если оно не меняет смысловой тип утверждения. Если замена неоднозначна, выбери обоснованный вариант и назови допущение — не сохраняй исходное слово только потому, что возможны варианты.

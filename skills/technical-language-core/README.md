# technical-language-core

Agent Skill для технического текста на языке документа: русский — полный каталог правил, английский — базовый пакет правил контролируемого английского, остальные языки — только языково-нейтральное ядро. Не задаёт структуру документов и не проверяет техническую истинность.

## Установка

Скопируйте каталог `technical-language-core` в директорию Skills вашего агента согласно его документации. Точка входа — `SKILL.md`.

## Состав

- `SKILL.md` — короткая инструкция, режимы, языковая политика, границы и рабочий процесс.
- `references/rules.md` — полный русский каталог правил с постоянными ID и силой.
- `references/english.md` — базовый английский пакет (не полный внешний стандарт).
- `references/terminology.md` — работа с общим справочником проекта и терминами на разных языках.
- `references/exceptions.md` — защита от механических правок.
- `references/examples.md` — примеры и контрпримеры.
- `evals/` — 100 кейсов (40 core, 45 расширенных, 15 language), скрипт прогона `run_eval.py`, слепая оценка и сборка `benchmark.md`/`benchmark.csv`.

## Проверка

Для работы навыка достаточно `SKILL.md` и `references/`. `evals/` — отдельный скрипт прогона.

```bash
cd skills/technical-language-core
python3 evals/run_eval.py \
  --runner-command 'your-llm --system {system_file} --prompt {prompt_file}'
```

`run_eval.py` подставляет в команду два пути: `{system_file}` — системный промпт, `{prompt_file}` — запрос пользователя. Команда должна напечатать ответ в stdout. Подробно — в [`evals/README.md`](evals/README.md).

## Источники

Справочник идей, на которые опиралась разработка правил. Это карта источников, а не утверждение о нормативном соответствии; ID правил навыка не являются номерами пунктов стандартов.

| Источник / материал | Полезный подход                                                                                       | Что не переносим автоматически                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| ГОСТ Р 58049—2017   | Однозначность и дисциплина формулировок                                                               | Жёсткие ограничения словаря, длины и грамматических конструкций для любого текста       |
| ГОСТ 19.106—78      | Ясность и определённость изложения программной документации                                           | Требования к составу и оформлению документов                                            |
| ГОСТ Р 2.105—2019   | Терминологическая точность и культура технического текста                                             | Универсальную применимость к любому жанру                                               |
| ASD-STE100          | Контролируемая терминология, различение процедурного и описательного текста; базовый английский пакет | Полный набор из 53 правил, официальный словарь, сертификация и заявление о соответствии |

Английский пакет `references/english.md` — рабочая систематизация ключевых норм контролируемого английского: пределы 20/25 слов, простые времена, `can/will/must`, условие перед командой, активный залог и защита идентификаторов. Официальный словарь не воспроизводится, полное соответствие внешнему стандарту не заявляется.

Точные пункты стандартов, цитаты и редакции нужно сверять с первоисточниками. Модель атрибуции отдельного правила: `direct` (прямое положение), `adapted` (адаптированная идея), `inspired` (источник повлиял на разработку), `rejected` (рассмотренный, но не принятый подход). `direct` не ставится без сверки текста и пункта первоисточника.
